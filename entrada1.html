Endurecer un servidor en 12 pasos

El hardening real empieza donde terminan los tutoriales rápidos. Antes de instalar más herramientas, conviene cerrar lo que no necesitas y entender qué está expuesto.

2026-11-20 7 min de lectura por 0xBLOG
/inicio /archivo /contacto
[nota] Los comandos son ejemplos para sistemas Linux basados en Debian. Adáptalos a tu distribución y conserva una sesión abierta mientras cambias la configuración de SSH, para evitar bloquearte fuera del servidor.

Un servidor expuesto a internet recibe intentos de acceso constantemente. No hace falta entrar en pánico, pero sí reducir la superficie de ataque: quitar servicios innecesarios, proteger las cuentas y mantener el sistema actualizado.

01. Actualiza el sistema

Empieza instalando las actualizaciones disponibles. Un sistema viejo puede conservar vulnerabilidades conocidas que ya tienen solución. 

sudo apt update
sudo apt upgrade

02. Crea un usuario administrativo

Evita usar la cuenta root para las tareas cotidianas. Crea una cuenta personal y dale permisos administrativos cuando realmente los necesite. 

sudo adduser operador
sudo usermod -aG sudo operador

03. Protege el acceso SSH

Usa claves SSH y desactiva el acceso directo de root. Antes de aplicar cambios, comprueba que puedes entrar con la nueva cuenta y la clave.

Edita /etc/ssh/sshd_config y revisa, según tu configuración, opciones como estas: 

PermitRootLogin no
PubkeyAuthentication yes
PasswordAuthentication no

Después de guardar, valida la configuración y recarga el servicio SSH. El nombre del servicio puede variar según la distribución.

04. Cierra los puertos que no utilizas

Revisa qué servicios están escuchando. Si no reconoces uno, averigua qué proceso lo abrió antes de detenerlo. 

sudo ss -tulpn

05. Configura un firewall

Permite únicamente el tráfico que necesitas. Si administras el servidor por SSH, autoriza ese acceso antes de activar las reglas para no perder la conexión. 

sudo ufw allow OpenSSH
sudo ufw enable
sudo ufw status verbose

06. Usa contraseñas únicas y autenticación adicional

No reutilices contraseñas entre servicios. Para cuentas importantes, utiliza un gestor de contraseñas y activa autenticación multifactor cuando esté disponible.

07. Reduce los servicios activos

Cada servicio instalado y olvidado puede convertirse en una puerta que no sabías que seguía abierta. Desinstala lo que no necesitas y revisa qué se inicia automáticamente. 

systemctl --type=service --state=running

08. Revisa permisos y archivos sensibles

Las claves, archivos de configuración y copias de seguridad no deberían ser legibles por cualquier usuario local. Comprueba permisos y propietarios, sin aplicar cambios masivos a ciegas.

09. Instala solo software de fuentes confiables

Prefiere los repositorios oficiales o proyectos cuya procedencia puedas verificar. Evita copiar comandos de instalación sin entender qué descargan y qué permisos solicitan.

10. Prepara copias de seguridad

Una copia que nunca se ha restaurado es solo una suposición. Automatiza los respaldos y prueba periódicamente que puedes recuperar los datos.

11. Configura registros y alertas

Los registros ayudan a investigar errores y accesos sospechosos. Define qué revisar, cuánto tiempo conservar los datos y cómo recibir alertas ante eventos importantes.

12. Documenta los cambios

Anota qué cambiaste, cuándo y por qué. Esa bitácora será más útil que intentar reconstruir meses después qué servicio dejó de funcionar y quién tocó la configuración.

Antes de cerrar la sesión

  • Confirma que puedes iniciar sesión con la cuenta administrativa.
  • Verifica que el acceso SSH sigue funcionando en una segunda terminal.
  • Comprueba las reglas del firewall y los puertos expuestos.
  • Asegúrate de tener una copia de seguridad reciente y recuperable.

El objetivo no es convertir el servidor en algo imposible de atacar. Es reducir riesgos, detectar problemas antes y evitar dejar abierta una puerta por simple descuido.
